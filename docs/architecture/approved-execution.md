# 批准的实验包与执行

本文定义 Issue #180 的实现契约；接口接入、测试结果与未完成项在 PR 中维护。

Control 的发布入口一次批准完整实验包，绑定环境模板、执行镜像、脚本或工具链配置、提交规则、确定性检查和评分规则。Agent 生成候选并完成构建验证，不能以构建成功替代教师批准。运行时读取获批准版本，不从候选草稿或当前编辑内容补齐配置。

批准入口在事务内校验并保存完整版本绑定及发布意图；本次动作就是教师批准，不要求先分别批准两个候选。环境模板仍由 Control 拥有，评测发布仍由 Evaluation 拥有。异步发布使用现有 Outbox、幂等和条件更新，完整包在全部组成部分就绪前不可供用户启动，单个子发布失败不能留下可用的半包。事务内不等待跨服务调用。

批准时同时冻结评测 provider 与执行镜像，异步发布和重试使用保存值，不能重新读取后来改变的配置来替换执行环境。就绪记录保存 Evaluation 实际返回的发布 revision；准入检查使用这一持久绑定，不猜测固定版本。一个发布中的程序与 Probe 使用同一获批准镜像，不能按步骤名称暗中切换镜像。

隔离候选构建依据项目允许的构建范围执行，绑定候选及构建请求，不以最终发布批准作为前置条件。构建成功后才呈现完整包供教师批准；构建授权不允许启动用户环境或发布共享内容，也不能使用伪造批准记录打通这条流程。

模型生成的 recipe 和文本文件先经过相对路径、重复文件、大小及项目范围校验，再由 Agent 写入隔离构建上下文和不可变工件存储。候选中的工件身份由服务端绑定真实存储结果，不能由模型编造。构建读取该上下文，发布使用真实输出镜像的 digest；未参与实际构建的基础镜像字段不能作为执行约束。

课程名称不决定执行后端。xv6 使用普通容器中的工具链和用户态 QEMU；安全靶场使用明确获准的容器网络和资源边界。二者复用环境与评测路径，不增加课程专用 RuntimeKind。镜像必须绑定 digest，执行参数来自批准包中的结构化配置，不能拼接用户输入生成宿主机命令。

Evaluation 保留现有任务状态与 Reconciler。冻结文件输入绑定不可变提交；实时 Probe 绑定目标环境、实例与观察时间，目标变化后不得将旧结果写到新实例。程序执行与 Probe 可共享真实重复的受限进程、Job 观察、取消与清理代码，输入和结果语义仍分别表达。

程序步骤的 `toolchainProfile` 是批准包内 JSON 文件的相对路径，使用 `evaluation.labweaver.io/program-profile/v1` 格式，包含可选的 `compileArgv` 和必需的 `runArgv`。编译步骤必须提供编译命令；解释执行可明确省略。参数逐项传入进程，仅替换 `{source}`、`{binary}`、`{submission_dir}`、`{evaluator_dir}` 四个路径标记。Probe 的 `playbookProfile` 同样指向批准包内的实际 playbook，不能通过课程名称选择写死的实现。

`supportFiles` 明确列出允许程序读取的包内辅助脚本和模块，空列表不授予额外读取权限。它不能包含私有用例源，运行时按具体路径授权，不开放整个评测材料目录。编译可以读取冻结的源码树并写入隔离构建目录；运行阶段对构建结果只读，另有每个用例独立的可写临时目录。多文件工程、解释执行和普通容器中的 QEMU 复用这套边界。

Evaluation 发布记录保存完整包及其工件 locator，执行前校验不可变工件的 hash 与大小。冻结归档和包内文件分别物化到任务临时卷，执行容器只读挂载输入。带访问权限的下载地址只进入受控 Secret；不得以预置 PVC、ConfigMap 中的用户文件或后来编辑的包补齐发布内容。

Worker 返回有界的结构化检查结果；确定性评分由已批准规则计算。启动失败、镜像不可用、协议损坏、读取失败和未知执行状态是基础设施错误，不转换为学生错误或通过。LLM 反馈与确定性结果分开存储，不接受它提供的分数或 Gate 决定。

Probe 的目标来自当前提交绑定的环境，并校验项目、拥有者、运行时身份和授权有效期。部署配置只选择执行器，不能为所有提交指定同一台目标机器。交互式 SSH 连接不能作为 Ansible 的执行代理；非交互执行须使用明确授权、限定目标和到期时间的能力。

Environment 为已授权的 Evaluation Probe 和私人 Work 配置签发独立的短期执行凭据。调用方服务身份必须与请求用途匹配，凭据绑定当前环境与执行任务；执行方验证目标主机密钥，并在执行前后检查运行实例。冻结采集凭据继续限制为只读 SFTP，不能通过放宽采集证书来取得命令执行权限。

执行结果先绑定当前 attempt 持久化，再清理 Job 和释放资源，最后完成步骤状态更新。恢复必须复用已保存结果与执行身份，不能因 Job 已删除而重新执行。用量投递同样先保存稳定事件 ID 和请求；同一 Job 的最终计量按 TaskRunId 与计量类别去重，重试不重新生成时间区间或事件 ID。

一次性任务使用 Resource 的 TaskRunId 租约。Evaluation 将项目、任务、租约与执行代次绑定到持久运行记录，再确认执行意图并启动 Job。取消、恢复和结果写入使用同一代次条件，旧 Worker 不能覆盖新尝试。实际执行对象清理完成后才确认释放；HTTP 接收请求、发出删除或 Worker 失联都不表示资源已经释放。

每次执行尝试拥有独立的 TaskRunId，由 Evaluation 生成并持久化，用户无需输入内部标识。需要集群执行的尝试以幂等请求交由 Resource 创建真实资源申请，审批前保留可查询的等待状态；同一尝试恢复时复用原申请，新尝试不能复用已释放的租约。用量与清理状态先持久化，再可靠投递；清理不明时可以上报待核实用量，但不能确认释放，不能等释放成功后才记录这类失败。

`FileAssertion` 对已验证的冻结清单进行有界文件项检查时，在 Evaluation 内完成确定性计算并保留执行代次条件，不创建额外 Job，也不生成并不存在的 GPU 或集群资源占用。Program 与 Probe 的实际 Job 继续使用 Resource 租约。

资源申请处于 Reviewing 时等待审批；Allocating 表示批准后可以领取并确认执行资源，确认成功后才启动 Job，不能等待尚未被确认的租约自行变成 Active。确认操作检查批准仍有效，并使用批准时长计算到期时间。任务的实际执行 namespace 与领取记录绑定，恢复时必须一致。审批等待与 Job 执行期间须维护 Worker 租约或持久化让出执行权，不能因调度租约过期而留下并行执行的旧 Worker。

取消或等待审批超时必须结束对应资源申请。Reviewing 请求由 Evaluation 经受限内部接口按 revision 取消；若审批已抢先完成，则读取新的领取状态并释放尚未交接的保留，不为释放而伪造激活。已启动执行对象的尝试仍先确认清理，再释放资源。取消与审批、续租、完成之间的竞态使用同一任务与执行代次条件处理。

私人 Work 仍由 Environment 管理生命周期。Agent 的配置排障只能使用该项目与工作环境允许的工具和预授权范围；需要重启或超出授权范围的改动先呈现影响并取得用户确认，不扩展 Agent 的平台权限。

项目创作入口区分私人 Work 与共享教学包。私人 Work 的拥有者可在预授权范围内确认自己的候选；服务端必须检查候选用途、项目归属和拥有者，不能仅因用户通过了通用创作接口授权便允许发布共享模板或评分规则。共享教学包继续由教师批准。
