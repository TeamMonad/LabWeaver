# C4 Architecture

## System context

LabWeaver 连接教师、学生、科研用户和平台管理员，通过 Keycloak/OIDC 建立用户身份，通过 Headscale/Tailscale 建立设备身份和私网可达性，通过业务服务实施课程、项目、环境、评测、资源和访问授权。

```mermaid
C4Context
    title LabWeaver System Context
    Person(teacher, "Teacher", "Designs and approves experiments and evaluations")
    Person(student, "Student", "Runs experiments and submits immutable results")
    Person(researcher, "Researcher", "Requests work environments and compute")
    Person(admin, "Platform Administrator", "Approves resources and operates policy")
    System(labweaver, "LabWeaver", "Agent-driven cloud-native lab platform")
    System_Ext(idp, "Keycloak / Campus IdP", "OIDC identity")
    System_Ext(tailnet, "Headscale / Tailscale", "Device identity and private reachability")
    System_Ext(cluster, "Kubernetes / KubeVirt", "Container, VM, and Job execution")

    Rel(teacher, labweaver, "Designs and approves")
    Rel(student, labweaver, "Runs and submits")
    Rel(researcher, labweaver, "Requests environments and resources")
    Rel(admin, labweaver, "Operates and approves")
    Rel(labweaver, idp, "Authenticates with OIDC")
    Rel(labweaver, tailnet, "Compiles and enforces access policy")
    Rel(labweaver, cluster, "Reconciles declared workloads")
```

## Container boundary

```mermaid
flowchart LR
    WEB[Gateway / Web] --> CTRL[Control Service]
    WEB --> ACCESS[Access Service]
    WEB --> ENV[Environment Service]
    WEB --> AGENT[Agent Service]
    WEB --> EVAL[Evaluation Service]
    WEB --> RESOURCE[Resource Service]
    WEB --> KEYCLOAK[Keycloak]
    ACCESS --> HEADSCALE[Headscale]
    ACCESS --> GATEWAY[Access Gateway]
    CTRL --> PG[(PostgreSQL)]
    ACCESS --> PG
    ENV --> PG
    AGENT --> PG
    EVAL --> PG
    RESOURCE --> PG
    CTRL <--> NATS[(NATS JetStream)]
    ACCESS <--> NATS
    ENV <--> NATS
    AGENT <--> NATS
    EVAL <--> NATS
    RESOURCE <--> NATS
    CTRL --> MINIO[(MinIO)]
    AGENT --> MINIO
    EVAL --> MINIO
    ENV --> OPERATOR[Environment Operator]
    OPERATOR --> K8S[Kubernetes / KubeVirt]
    EVAL --> EXECUTOR[Build / Evaluation Executor]
    EXECUTOR --> K8S
```

The diagram defines intended boundaries, not implementation completion. Current evidence is recorded separately in the implementation status.
