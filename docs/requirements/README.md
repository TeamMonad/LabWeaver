# 产品需求

LabWeaver 面向教师、学生、科研用户和管理员，提供 Agent 原生的教学与科研工作环境。现有架构见 ADR，Sprint5 目标见 [重构方案](../plans/sprint5-refactor-plan.md)。目标不表示已经实现，实际交付见关联 Issue/PR。

| 用户 | 主流程 |
| --- | --- |
| 教师 | 上传材料、描述目标、生成并验证配置和镜像、预览、一次批准完整实验包、查看结果 |
| 学生 | 打开实验、启动或继续、终端/桌面/SSH 工作、提交、查看确定性评测与反馈 |
| 科研用户 | 选择项目、模板或软件需求、资源和时长、查看估价、申请 Work、连接配置、续期和回收 |
| 管理员 | 配置资源池/GPU/费率、审批、查看用量费用、调整预算和处理故障 |

普通用户无需理解 Provider、NATS、Kubernetes 对象和内部 revision。高级配置使用真实表单与服务端校验；YAML 可作高级入口，不是唯一入口或第二配置真源。

实验扩展主要增加模板、脚本或镜像包与行为测试。xv6、受控安全实验和 CTF 用于检验通用性，不增加专用业务服务或 RuntimeKind。

Sprint5 的 GPU 目标包括独占、MIG、容器时间片和官方支持且获授权的 VM vGPU。规格展示共享方式、隔离、显存和硬件限制。未知用量不能伪装为零。

项目 Credits 支持发放、转移、预占、结算和调整，不接真实支付。预留停止保持权利和期间费用，提前显式释放按未用时长退款。可抢占资源遵守余额、抢占和数据保留规则，具体语义以重构方案为准。

保留六个业务服务，采用细分 Issue 和功能 PR，不固定人员分工。Slurm、多集群、共享数据集、通用多环境 DAG、支付网关和完整 CTF 竞赛运营延后，不保留空实现。

完整用户文档、部署运维文档和 API 使用说明与功能一同交付。测试关注可完成的用户旅程和失败行为，不以重复报告或状态表维护进度。
