# 开始使用 LabWeaver

## 登录与项目

管理员开通组织账号并授予相应角色后，从平台首页登录。左侧导航列出当前账号可用的全部功能；个人 Work 使用同一账号，无需切换身份。

首页“进行中”只显示当前项目的事项：运行中的环境、未完成的生成与配置任务，以及待审批或分配中的资源申请。等待审核的任务可以从“去审核”直接进入审核页。每个未完成的任务按轨道（Work 配置、环境、评测）显示当前尝试的阶段和第几次尝试；之前失败的尝试不会显示在首页，完整记录在任务所属页面查看。某条轨道等待人工审核或资源审批时，任务下方会写明它在等什么、处理后是否自动继续；等待资源审批时可点击“查看资源申请”。首页不显示进度百分比。某个任务的进度读取失败时，只有这一行显示原因和诊断信息（可重试的错误可点击“重试”单独重新读取），其他任务和首页其余部分照常显示。首页在打开、切换项目、点击“刷新”和从其他标签页切回时更新；页面在后台时不自动刷新。首页的资源申请列表可能不完整（平台暂时只返回你能看到的申请，且不分页），完整记录在“资源申请”页查看。

点击顶栏“退出”后，浏览器会完成组织登录系统的退出并返回首页。页面提示登录失效时，重新登录再继续原项目；不要重复提交结果不明的任务。

同一浏览器的所有标签页共用一个登录会话。在其他标签页退出或换成另一个账号后，本页不会用新账号提交旧页面里的内容：

- 写操作的安全校验只对发起它的账号有效。写操作被拒绝时，页面提示“登录会话已在其他页面变化或安全校验已失效，这次操作没有执行。”平台不会自动重试这次操作。
- 平台随后重新确认当前账号。账号未变时，核对页面内容后手动重新提交。
- 账号已变化时，页面按新账号重新加载，未提交的表单和上一账号的列表会被清除，旧账号尚未返回的结果会被丢弃。项目按新账号的项目列表重新确认；新账号无权访问链接中的项目时，页面显示项目恢复入口。
- 会话已结束时，按提示重新登录。

先在“项目与工作空间”创建项目，或由项目负责人将你加入已有项目。平台教师/管理员且有成员管理权限的用户可以按组织账号的显示名称或 `username` 搜索组织目录并选择成员；其他有成员管理权限的成员（例如学生管理自己的私人项目时）需输入受邀者准确的 `username`。项目编辑、归档和成员管理按对象动作授权：`manager` 可管理成员但不能管理运行策略，`owner` 受项目根所有权保护，平台管理员仅能执行契约明确允许的全局动作，其他成员按其 `objectRole` 查看或操作。顶栏项目选择器决定当前操作的归属。地址栏中的 `projectId`、页面标题、选择器和页面数据始终指向同一个项目，刷新或分享链接后仍打开同一项目。选择器支持键盘操作：按上下方向键移动，按 Enter 选择，按 Escape 关闭。切换项目后，页面会重新加载该项目的数据，并清除上一项目中选中的环境或任务。

每个成员在项目中有一项“项目职责”，与教师、学生身份分开。添加成员时：

1. 在“教学身份”中选择学生或教师。
2. 在“项目职责”中选择查看者、操作者、编辑者或管理者。下方说明会列出该职责允许的操作。
3. 点击“添加成员”。成员列表显示每个成员的项目职责。

查看者只能查看项目、成员和环境。操作者还可以启动、停止和重启环境。编辑者还可以编辑项目、新建 Work、创建和删除环境、签发访问授权和提交评测。管理者还可以管理成员。项目负责人在创建项目时确定，不能通过成员管理授予。只有项目负责人和平台管理员可以归档项目。课程学生需要编辑者职责才能创建实验环境和提交评测。

页面只显示你的职责允许的操作。缺少某项职责时，对应按钮会隐藏或置灰，并说明缺少哪项职责；请联系项目负责人调整。页面在权限有效期结束、页面重新显示和操作被拒绝后重新读取你的职责。服务端仍会检查每次操作，按钮可见不代表操作一定成功。成员被移除后，已打开的终端和事件连接最多在 60 秒内关闭。

打开的链接指向你无法访问的项目时，页面显示“无法打开链接中的项目”，并说明“项目不存在或你无权访问”；项目可以读取但不在你的项目列表中时，同样不能在这里打开。页面不会显示其他项目的数据。点击“切换到「项目名称」”回到可访问的项目，或点击“查看我的项目”重新选择；如果你认为应该能访问该项目，联系项目 Owner 或管理员确认。

项目列表加载失败时，项目页面显示“暂时无法确认当前项目”，不会打开任何项目的数据。点击“重试”，列表加载成功后页面才会打开。

Access 的登录入口是门户顶层导航 `GET /auth/login?return_to=<门户路径>`。每个标签页都有独立的 state、PKCE、nonce 和事务 Cookie；不要把另一个浏览器或标签页的 callback URL 复制过来。非法 `return_to`（外部 URL、`//`、反斜杠或控制字符）返回 `400 / LW_AUTH_OIDC_RETURN_TO_REJECTED`。事务 Cookie 缺少或跨浏览器使用返回 `401 / LW_AUTH_OIDC_BROWSER_REJECTED`；重放或过期返回 `401 / LW_AUTH_OIDC_STATE_REJECTED`。

退出请求必须带当前 `Origin` 和 CSRF token。Access 撤销 BFF 会话、清理会话 Cookie，并终止该 BFF 会话的浏览器 Console 连接；随后按响应中的 `logoutUrl` 顶层导航到 Keycloak。SSH 会话使用独立 AccessGrant，按 grant 到期、显式撤销及成员/环境授权变化的规则收尾，BFF 退出不会错误地声称已撤销独立 SSH grant。

项目负责人在“项目 AI 设置”选择可用模型、确认材料范围并设置调用预算。模型服务地址和凭据由管理员在部署侧配置，普通用户无需填写。材料只应包含本次任务所需且已获授权的文件。

Agent 生成、配置和评测 LLM 建议的模型请求通过平台计量网关统一预占项目 Credits。管理员必须为
该模型完整配置 input、output、cache-read、cache-write 四类 token 单价、token 基数和单次最大预占；
缺价或余额不足时调用会被拒绝，不会把请求发到模型提供商。实际结算使用调用准入时的费率快照，
不会从模型 USD 预算换算 Credits。取消或断流时，只有可信完整终态 usage 才最终结算；部分 token
观察会保留为待核实，不把未观察输出当作零，也不代表免费。首次未知一小时后释放剩余预占，迟到
成本由平台承担；重试前先查看原任务和预占，不通过重复发送不确定请求来探测结果。

## 教师准备实验

1. 选择项目，从教师工作台进入材料页面，上传包含题面、初始源码、样例及环境要求的材料目录。
2. 上传完成后，在“选择交给模型的文件”中勾选这次生成需要模型读取的文件，再点击“启动实验生成”。平台不会自动选择整个材料包；未勾选的文件即使在同一目录也不会交给模型。没有勾选文件时启动按钮不可用。“全部勾选”只在你点击时生效。换用另一个材料包或新版本后需要重新勾选。等待期间查看任务状态；资源待审批时由管理员处理相应申请。启动被拒绝或任务因模型输入授权失败时，页面先显示中文原因和下一步，再给出诊断码和请求 ID：文件选择无效时刷新材料包后重新勾选；会话或权限不再允许时确认项目成员资格、必要时重新登录，再新建一次任务。
3. 打开“审核与发布”。左侧列出当前项目的实验生成任务，不需要复制任何 ID。
   - “可以审核”：打开后在右侧审核。
   - “未完成”：回到材料页，沿原任务继续处理。
   - “已有发布版本”：页面读取发布时的批准记录，核对材料包、环境和评分规则是否与当前版本一致。完全一致时只显示发布结果；任何一项有变化时，提示需要重新审核。
   - 左侧只列出最近 50 个生成任务。读不到已发布版本或其批准记录时，页面暂停批准，刷新或重试后再批准。
4. 依次查看各标签页：“概览”显示资源规格和每次生成的结果，失败的尝试和诊断码保留在记录中；“环境与权限”显示学生入口、资源和平台当前返回的安全策略；“评分规则”显示每个步骤的分值、检查方式和测试组；“材料”列出材料包文件；“技术详情”列出将要绑定的候选、镜像身份和批准后的发布记录。页面目前没有学生视角预览，也不显示特权模式、capability 用途或发布前估价。
5. 勾选确认并填写批准说明，点击“批准并发布”。一次批准绑定这一版的材料包、环境、运行权限、镜像和评分规则，并自动发布。网络失败后重试或重复点击沿用同一次提交，只产生一个版本。之后材料或配置有变化，会生成新的候选，需要重新审核；已发布的版本不受影响。发布完成后，任务移到“已有发布版本”，可在“已发布环境模板”中查看。链接中的批准记录不属于当前版本时，页面会忽略它并提示，当前版本仍可审核。发布失败时页面显示原因和诊断码，把诊断信息发给平台管理员处理。
6. 评测含 AI 评语步骤时，发布完成后在“评分规则交给模型的设置”中决定评语步骤能否读取评分规则文件。课程当前的授课教师能查看材料项目时可以看到这些设置；修改还需要材料项目的编辑权限，没有编辑权限、或页面暂时无法确认你的项目权限时，页面只显示当前设置和原因，不提供修改按钮。每个评分规则默认隐藏，不会交给模型：
   1. 点击“设为课程内公开”。这只改变可见性，评分规则仍不会交给模型。
   2. 点击“批准交给模型 <模型名称>”。批准针对项目 AI 设置当前使用的模型；之后更换模型，原批准不再生效，页面会提示需要重新批准。页面确认 AI 设置与评分规则属于同一策略版本之前，批准按钮不可用。页面会自动重新读取一次；读取失败或版本仍不一致时，页面先显示原因，再给出诊断码和请求 ID，服务返回的原始说明放在“技术详情”中。点击“重新核对”会同时重新读取评分规则和 AI 设置，核对完成前仍不能批准。
   3. 不再允许时点击“撤回模型批准”，或点击“设为隐藏”。修改可见性会同时清除已有的模型批准。撤回批准、以及会清除已有批准的“设为隐藏”，都先弹出确认框，说明之后新开始的 AI 评语调用不会再读取这个评分规则；点击确认才保存，点击“取消”不做更改。没有批准时设为隐藏不需要确认。
   保存被拒绝时，页面先显示原因，再给出诊断码和请求 ID；规则或 AI 设置已被他人修改时，页面自动重新读取两者，按最新的模型核对后再操作。
7. 将学生加入项目。发布后的实验版本供学生提交资源申请、审批通过后进入环境使用。成员搜索和发布操作完成后刷新项目，确认成员显示名称、username 和角色正确。
8. 从环境页面查看有权管理的实际运行环境。修改运行实例与修改共享实验版本是不同操作；学生从自己的评测结果页面查看提交结果。

## 学生完成实验

1. 选择已加入的实验项目，进入“我的实验”，点击“申请实验环境”，选择已发布的实验模板，再点击“选择并申请资源”。实验项目可以关联课程，也可以独立使用。资源申请页会预先选好这个实验版本；CPU、内存、存储、时长以及 GPU 等资源请按实验说明填写，平台按审批通过的资源创建环境，没有申请 GPU 就不会分配 GPU。核对后点击“提交资源申请”。
2. 回到“我的实验”查看“实验资源申请”。“待审批”列出等待管理员审批的申请，可点击“查看申请”打开资源申请记录；“已拒绝”列出被拒绝的申请和原因，可点击“重新申请”用同一实验版本提交新的申请。审批通过后，申请出现在“已批准的申请”中，点击“进入环境”打开环境控制台。平台仍在分配资源、创建环境时，页面显示“环境准备中”，这不是失败，稍候再点击“进入环境”即可；重复点击、重试或刷新页面后再点击都沿用同一请求，不会重复创建环境。没有已批准的申请时，页面提示先提交资源申请。等待时可以离开页面，返回后继续查看。
3. 环境就绪后打开环境控制台，签发访问授权并连接浏览器终端或图形控制台。
   打开容器实验的 Web 应用时，从环境页点击平台返回的应用入口。新标签页会经过短期一次性交接，
   最终地址位于此访问授权独有的运行时主机，而不是门户或其他应用主机；这是正常的安全隔离，
   应用不能读取门户登录会话，也不能以你的身份读写另一个应用。交接时绑定信息会立即从地址栏清除。
   不要复制或分享地址中的交接 token。入口或会话过期时回到门户重新点击，退出平台后旧应用请求
   会立即失效；运行时写操作还需当前访问授权允许编辑。浏览器终端和图形控制台使用原 Console 流程。
4. 在自己的运行实例内完成题目要求的源码或系统配置修改。提交时选择对应评测入口；冻结提交针对提交时的输入版本，实时配置检查针对当前实例。
5. 提交后，在环境页“实验提交与凭据”或“评测结果”页查看这次提交的进度：排队与准备、资源审批、执行评测和结果。阶段来自平台记录，页面不显示百分比；等待时页面自动更新，页面在后台时暂停更新。浏览器只记住你在这里提交的提交编号，提交时间、实验名称和进度都要等平台确认这次提交属于你之后才显示；在同一浏览器离开后返回仍能看到这次提交。退出登录或换账号登录后，浏览器清除这些记录；换设备后，出分时结果会出现在“评测结果”列表。
6. 某一步的上一次尝试未完成时，页面显示“尝试未完成”和尝试次数，平台处理期间不会记为 0 分。资源审批超时后，评测以“评测未完成 · 不计分”结束，可以回到实验环境重新提交。
7. 在评测结果中查看成绩、失败原因和反馈。“评测完成 · 0 分”是正常评测得到的分数；“评测未完成 · 不计分”和“已取消 · 不计分”表示评测没有完成，不是 0 分。反馈问题时，提供详情页“技术信息”中的评测编号和诊断码。修改后重新提交，不改变已提交版本或共享评分规则。
8. 完成实验后，停止环境可保留工作目录和磁盘，供之后重启；需要归还资源时删除环境，并等待页面显示实际释放。删除前备份需要的文件。“停止中”“释放中”和“已释放”分别表示不同阶段。

## 个人 Work

1. 打开“Work 环境”。页面列出当前项目的 Work 及其固定的模板版本，点击“连接”进入已有 Work。创建和连接 Work 不需要配置模型。页面顶部按平台返回的项目 Agent 配置说明 Agent 是否可用：未配置模型或模型在当前部署中不可用时显示“Agent 已关闭”和原因，只关闭 Agent 生成与配置；配置读取失败时显示“暂时无法确认 Agent 是否可用”及诊断码，这不等于项目没有模型。两种情况下手工创建和连接 Work 都不受影响。
2. 在“新建 Work”中选择一个已发布的 Work 模板。页面只列出用途为 Work 且未撤回的版本；课程实验模板不出现在这里。卡片显示模板名称和版本、运行方式（容器或虚拟机）、来源（手工发布或 Agent 生成并审核）、发布时间、说明、支持的能力（浏览器终端、桌面、SSH、Web 应用、文件、Agent）和固定的镜像。项目当前没有可用模型时，Agent 能力标为“项目当前不可用”。创建后 Work 固定使用这个版本，模板发布新版本时不会自动替换已有 Work。
3. 点击“下一步：选择资源与时长”。资源申请页面会预先选好该模板版本；填写 CPU、内存、磁盘、时长和所需 GPU，点击“估算费用”查看按当前费率计算的 CREDITS 合计与各项明细，核对后提交，等待审批。估价不预占资金也不占用容量；缺少费率时页面显示原因，不显示为零或免费；所选 GPU 当前不可用时不能估价。审批通过、环境激活前，平台按批准的规格和时长预占项目 Credits，可用余额不足时不会创建环境。资源申请页下方的“项目 Credits 账户”显示本项目的可用余额、已预占、已支出、待核实用量以及账目和预占记录。
4. 回到“Work 环境”查看进度。“Work 申请”的“准备中”列出已提交但还没有环境的 Work，写明等待审批、正在分配资源、正在创建环境或资源即将到期；平台返回诊断时一并显示原因和诊断码。申请变化期间页面自动刷新，审批通过后平台自动创建环境，Work 随即出现在“项目中的 Work”。
5. 申请被拒绝、已取消或已到期且没有创建 Work 时，列在“未创建成功”中，并显示原因。这些申请不会自动继续：点击“查看资源申请”查看记录，或点击“用同一模板重新申请”提交新的申请。不要在原申请仍在“准备中”时重复提交。
6. 当前项目没有可用的 Work 模板时，“发布手工 Work 模板”会自动展开；有模板时点击它展开。发布需要项目编辑职责，并且是项目所有者、平台管理员或有项目管理（管理成员）职责；不满足时表单不出现，页面说明缺少哪项职责，项目职责尚未读取到时也不能提交。符合条件的成员按以下步骤发布，不需要模型或 Agent：
   1. 选择一个管理员登记的平台镜像（列表只显示当前可用的镜像）。发布同一模板系列的新版本时，可以先在“以已有手工模板为起点”中选择旧版本，复制它已审核的配置。
   2. 填写模板名称、模板系列标识和说明（用途、预装软件）。同一系列的较新版本可供已有容器 Work 确认兼容升级；资源或权限变化需要新的资源申请。
   3. 填写默认 CPU、内存和存储。容器模板再选择应用协议、端口、网络，以及是否提供浏览器终端；虚拟机模板固定通过 SSH（端口 22）连接，不能访问外部网络。
   4. 填写平台管理员提供的运行位置（provider binding）、安全配置（security profile），虚拟机模板还需填写磁盘存储类。
   5. 选择材料保留期限，填写审核说明，勾选确认后点击“发布模板”。缺少必填项时，按钮下方说明还缺什么。
   6. 发布受理后，版本出现在模板列表中即可选择。发布失败时页面先显示原因，再给出诊断码和请求 ID。除非平台明确说明发布内容不合格（例如配置无效、材料保留期限已过、镜像与配置不匹配），页面都提示“发布结果待确认”：权限被拒绝、操作仍在进行、服务不可用或网络中断时，平台可能已经受理这次发布。此时点击“重试”或再次提交相同内容会沿用同一请求，不会重复发布；刷新页面、折叠后重新展开表单，页面会恢复同一份发布内容并提示“上次发布的结果尚未确认”，重新勾选确认后提交即可。修改内容会作为新的发布。退出登录或切换到另一个账号会清除这些未确认的发布；网络暂时中断导致身份无法确认时不会清除。请求因权限被拒绝时，页面重新读取你的项目职责。
   现有“软件配置”中的 Agent 生成入口仍需要项目 AI 设置，不是手工 Work 的前置条件。
7. 点击 Work 的“连接”打开环境页。“连接”分开显示实例状态和连接状态，两者都直接来自平台返回的连接信息：实例运行中不代表已经可以连接。连接入口仍在准备时显示“连接准备中”；平台还没有确认入口可用（例如虚拟机的 SSH 尚未完成握手）时显示“无法确认”；入口不可用时显示“入口不可用”，并给出平台诊断码；入口就绪但没有访问授权时显示“待授权”，授权生效后显示“可连接”，授权过期或无法确认时显示“待重新授权”。等待期间页面每隔几秒自动重新读取，最长约 10 分钟；之后点击“重新检查”。页面切回前台时也会立即重新检查。平台提供登录环境内系统的说明时，页面在“登录环境内系统”中列出；平台账号只用于签发访问授权，不会自动登录环境内的操作系统。
8. 在“待授权”或“待重新授权”时点击“签发授权并连接”或“重新签发并连接”。授权生效后，页面按平台为这个授权返回的控制台能力打开第一个浏览器控制台（终端或桌面）；平台没有返回浏览器控制台时停留在概览，使用列出的 SSH 或 Web 应用入口。“连接方式”只列出平台返回的方式：浏览器终端或桌面按访问授权的控制台能力列出，SSH 和 Web 应用按已登记的入口列出。
9. 启动、重启或重试 Work 时，如果页面提示“资源使用授权已到期、被回收或尚未生效”，这个 Work 不能继续运行。点击“提交新的资源申请”，资源申请页会预先选好原模板版本；申请审批通过后，平台会创建一个新的 Work。如果页面提示“旧资源批准没有权限投影”，说明这份资源批准是在平台记录权限投影之前做出的，不能再用于新的启动、重启、恢复或升级；页面不提供“重试”，同样点击“提交新的资源申请”。平台暂时无法核验资源授权时，页面说明本次操作没有执行，并显示诊断码和请求 ID，稍后重试即可。
10. 容器 Work 的环境页“模板版本”列出同一模板系列中更新的已发布版本。点击“升级到 vN”后，确认框说明升级会重启 Work：终端、桌面和 Web 应用连接断开，正在运行的程序结束；`/workspace` 中的文件保留，`/workspace` 以外的改动（例如另行安装的软件、临时文件）会丢失。点击“升级并重启”后才提交，一次确认只提交一次。升级沿用这个 Work 原有的资源批准和使用授权，不另开租约。
11. 升级受理后，“模板版本”显示“升级目标版本 vN”，并注明升级操作成功后才表示新版本已在运行；状态行显示“模板升级 vM → 目标版本 vN”和平台返回的操作状态，页面自动刷新。成功后显示“升级已完成”；失败时显示“升级没有完成，新版本没有运行”和诊断码，`/workspace` 不会因此被删除，可用顶部操作栏的“重试失败的操作”再次升级到同一目标版本。升级请求的结果未确认（例如网络中断、服务暂时不可用）时页面提示“升级结果待确认”：点击“重试”、刷新页面或再次确认同一版本都会沿用同一请求，不会重复升级。
12. 升级被拒绝时，页面先显示中文原因再给出诊断码和请求 ID，原 Work 和 `/workspace` 不受影响：
    - “资源或权限变化需要新的资源申请”：目标版本的资源、网络、安全、入口、运行位置或端口与原批准不同。点击“为 <模板名称> vN 提交新的资源申请”，审批通过后平台会创建新的 Work。
    - “所选版本不属于这个 Work 的模板系列”或“所选版本未发布、已撤回或当前不可用”：点击“刷新版本列表”，从更新后的列表中重新选择同一模板系列的可用版本。
    - “旧资源批准没有权限投影”：点击“为 <模板名称> vN 提交新的资源申请”；页面不提供“重试”。
13. 虚拟机 Work 不能在原 Work 内升级模板：“模板版本”说明需要导出/导入流程、当前不可用，并给出“用 <模板名称> vN 新建 Work”入口，新建后自行迁移数据。
14. 需要配置软件时，在“软件配置”上传配置要求，在“选择交给模型的文件”中勾选模型需要读取的文件，再选择目标 Work；不勾选文件不能提交，平台也不会自动发送整个材料包。在“生成 Work 模板”中启动生成前同样需要勾选文件。审核生成的脚本、权限和重启影响后批准执行。任务因模型输入授权失败时，尝试记录先显示中文原因和下一步，诊断码保留在“查看诊断”中。
15. 查看执行结果。失败后先检查原任务状态，再使用页面提供的恢复或重试操作；重试同一配置应避免重复提交，实际新增用量仍可能产生费用，系统不得对同一用量重复入账。
16. 停止并重新启动环境后，按模板和页面的数据保留说明检查工作区；需要保留的软件配置应写入模板声明的持久化路径，容器 rootfs 中的临时安装不视为持久化。确认任务完成后从页面释放环境并查看费用。

Work 和 Experiment 首次创建都需完成 Resource 申请、审批及原租约资金覆盖。Resource 自动交接并创建同一目标环境；`POST /environments` 必须提供该真实申请的 `resourceRequestId`，只附着到原创建操作，不能绕过授权或再分配一份资源。已有实例在原租约仍有效时可启动、重启或恢复，服务端重新核对当前配置授权与资金覆盖，不要求为同一版本每次提交新申请。租约失效、撤销或容量已释放时不能直接启动，须重新走正式准入。估价不能替代正式资金与容量分配。

手工 Work 可直接使用服务端 `estimateProjectResourceCost`（`POST /api/v1/projects/{projectId}/resource-cost-estimate`）核算所选资源和时限，不需要模型。请求分别提供计算与存储的起止时间；停止后继续保留磁盘时，存储区间可长于计算区间。结果包含固定费率版本、明细和 Credits 总额；缺价、价格覆盖缺口、未知 GPU 类别等情况明确失败。估价是无资金与容量副作用的读取，不能替代 Resource 正式资金准入。

环境详情接口将 `connection.instanceReady` 与 `connection.state` 分开返回，并提供 `guestInstructions`。VM 已运行但 SSH 握手尚未成功时，连接状态为 `unknown`，不伪装为健康入口。平台身份不会自动登录 guest；桌面使用镜像管理员说明的 guest 登录方式，SSH 先登记个人公钥并经平台网关连接。Agent 配置读取失败是失败，不等同于“未配置模型”；手工 Work 的创建和连接不读取项目模型配置。

兼容升级复用原 request、approval、claim、lease 和资金 hold，不新增 reservation，也不重复占款。
升级入口及后台每次新计算前都重核当前权限、发布状态和原资金覆盖；撤权、撤回、未发布、
跨模板族或资源/权限变化均拒绝。`LW_WORK_TEMPLATE_UPGRADE_REQUIRES_RESOURCE_APPROVAL` 表示需要新授权；
`LW_RUNTIME_AUTHORIZATION_REAPPROVAL_REQUIRED` 表示旧批准缺少权限投影，需要重新提交资源申请。
这些入口拒绝发生在撤销访问授权、改写目标模板和重启之前，不改变原实例或工作目录。
受理后的运行失败保留可查询的失败状态；恢复沿原租约，实际新增用量仍可能产生费用。

VM Work 不支持原地模板升级：服务端返回 `LW_WORK_TEMPLATE_UPGRADE_UNSUPPORTED_FOR_VM` 和中文原因“需要导出/导入流程，当前不可用”。拒绝时不重建实例、不修改原模板或磁盘。

## 普通容器的运行用户与能力

本节说明已发布配置和后端执行边界，不表示页面已经提供所有字段的编辑开关。先核对所选模板版本的
运行声明和管理员策略，再申请资源；权限增加需要新的配置版本及相应授权，不能通过重启扩大旧批准。

- `runAsUser` 未指定或为 `null` 时，使用同一已验证平台配置的默认容器 UID；平台默认是 `0`（root），
  管理员也可配置非零 UID。显式 UID 按声明执行，保留值 `4294967295` 不可用。root 不等于特权容器。
- 普通容器仍为 `privileged=false`，默认不添加 capabilities，先丢弃全部能力，再只加入本次声明且获准的
  集合。`NET_ADMIN` 等能力必须在平台可执行清单和允许范围内，并通过相应对象/课程或项目授权；
  `ALL`、未知能力及 `SYS_ADMIN`、`BPF` 等广泛内核能力不能用来绕过拒绝。
- `allowPrivilegeEscalation` 只接受 `false` 或 `null`（缺省或 `null` 统一按 `false`）；普通切片在 Rust
  配置语义校验中明确拒绝 `true`，不会由 Provider 静默改成 `false` 后执行。使用 root 也不例外。
  `readOnlyRootFilesystem` 默认关闭，因此普通容器系统目录可以临时写入；它与 UID 分开表达。
  seccomp 保持 `runtime_default`，不支持关闭。
- 容器系统层的安装和改动不等于持久化工作文件。`/workspace` 仍是独立工作盘；需要保留软件环境时，
  使用已有的模板/镜像构建流程。停止保盘不代表保存临时系统层，也不提供七天回收站或导入导出。

部署方只会为 Environment 自己创建的运行空间选择合适的 Pod Security 准入：无额外能力使用 baseline，
有能力声明的空间可能标为 privileged，以允许 baseline 不接纳的能力。这个标签不表示 Pod 被授予
`privileged=true`，也不给工作负载 Kubernetes API 权限；平台服务、Evaluation 和 builder 不随之提权。
使用管理员预置运行空间时，平台不会修改其安全策略；不符合该空间准入的配置会失败，请联系管理员核对，
不要自行放宽整个集群或添加宿主挂载。实际能力还受镜像、安全模块和运行集群约束，字段存在不是实机验收。

普通容器的带对象 Apply 和会创建或变更计算的动作，必须携带从可信模板规格、同版本授权回执和部署配置
重建的完整计划：对象数量、顺序、内容都要一致。不能只保留 Pod/Deployment 而省略 NetworkPolicy、
ResourceQuota 或 LimitRange，也没有携带计算对象的“稀疏计划”或“有序子集”例外。执行器用同一 canonical
摘要规则重算收到的对象列表，再核对可信计划摘要；请求自报的 securityContext 或摘要不能单独授权执行。
对象缺失、多出、重排或内容漂移均在 Kubernetes 写入前拒绝。若旧配置声明了 `allowPrivilegeEscalation=true`，
应修正为支持的配置并重新走原版本/权限流程；平台不改写旧声明来降权运行。

创建、启动、重启、重置及会产生计算的恢复都会重新核对原运行权限和资金覆盖。管理员保存 desired 后，必须按正常流程
验证 applied 版本才会用于新运行授权；旧批准不会悄悄取得新默认 UID 或更大的能力范围。权限失败时先查看
原申请、模板版本与诊断，不要重复创建或尝试添加更强权限。VM 仍使用原 guest 用户、SSH 和持久系统盘行为，
不把这些容器字段当作 guest UID/能力开关。本切片不提供真正的 privileged 或 DinD。

## SSH 与环境生命周期

在“SSH 公钥”登记自己的公钥，私钥留在客户端。环境就绪并获得访问授权后，从环境页面复制完整 SSH 命令并实际连接。连接中断后先检查环境与授权状态，再使用页面命令重连；授权过期时从界面重新签发，撤销后不能继续使用原授权。

停止环境、删除环境和释放资源是不同操作。提交停止不代表已停止计量：环境实际停止后，计算用量才停止计量；保留的工作目录和磁盘继续计入存储用量，直到删除。GPU 容量是否保留取决于环境类型和项目资源配置，以资源与费用记录为准。删除环境会永久删除其工作目录和关联磁盘中的数据，执行前备份需要的文件并阅读页面说明。

点击“停止”或“重启”后，页面先弹出确认框，说明会断开的会话和用量变化；GPU 容量是否保留以资源与费用记录为准。点击确认后才提交操作，点击“取消”或按 Escape 不做任何更改。“启动”不需要确认。确认框打开时焦点默认在“取消”上。提交停止或回收请求后，等待界面显示实际完成；“释放中”不表示容量已经可供下一项任务使用。

环境控制台只在环境处于启动、停止、重启等变化过程中自动刷新状态；环境稳定后停止自动刷新，页面在后台时也暂停，切回标签页时立即刷新一次。需要最新状态时点击“刷新”。

部署管理员可以把指定项目的普通容器 Work 放在已配置的运行空间；用户不需要选择或填写 Kubernetes namespace。环境连接、终端、应用入口和提交时冻结的工作文件都读取同一实际落点。配置变化不会把已有 Work 自动迁到新空间；空间被重建或归属不匹配时操作会拒绝，不会覆盖同名资源。

在这种部署中，停止只退役计算，保留工作盘。删除仍会在确认运行 Pod 和引用工作盘的 Pod 全部消失后清除本 Work 的盘，不删除其他 Work 或管理员维护的空间策略。清理失败时先查看原操作的原因并重试，不要重复创建环境或手动删除磁盘。当前没有七天回收站、恢复或导出能力，删除前仍须备份。

运行实例使用资源申请中已批准并完成资金覆盖的原租约。平台交接成功后，Work 和 Experiment 都沿用这条租约，不为重试另建环境或重复预占。续期只增加原租约的新增时间窗口；停止保留租约权利与工作盘，不自动退还预留费用。删除请求受理后仍需等待计算和磁盘实际清理完成；核实释放后才结束原租约并处理剩余额度。失败或状态未知时不要把资源视为已释放。

## 使用 GPU

申请资源时选择管理员提供的 GPU 类别和模式，并确认模板支持相应容器或 VM。独占、容器时间片和 VM vGPU 的容量分别由实际设备配置决定；容器时间片只提供共享份额，不提供独占显存或固定比例算力。没有可用容量时，按申请状态等待或联系管理员，不要重复创建申请。

进入环境后运行任务所需的 CUDA 计算，确认数值结果符合预期。VM 中同时确认驱动和许可证状态；设备名称可见不代表计算已经可用。完成后释放环境，等待资源使用授权实际回收，再申请下一项任务。

## 管理员处理资源与费用

管理员先配置可用镜像、执行资源、GPU 目录和费率，再处理用户申请。审批前确认项目、申请人、用途、资源规格和期限。GPU 目录应对应实际可分配设备；设备不可用时处理等待或拒绝申请。

在“Credits、预算与费用”页面选择已授权项目，按环境或任务查看实际计算和存储区间、CPU、内存、存储及 GPU 用量、结算与预算提醒。教学与个人 Work 都进入统一核算。缺少费率、未知用量及尚未结算的记录应继续处理，不能当成零费用；已有历史费用不表示当前任务已结算。费用用于核算，不代表已经支付。需要调整时填写金额和原因；调整追加记录，不覆盖原费用。

### 配置费率

项目 Credits 只按币种为 `CREDITS` 的费率预占和扣收，费率表单默认填写 `CREDITS`；改成其他币种时页面提示该费率只用于预算核算。

1. 在“资源费率”中选择计费单位。CPU、内存、存储按核心小时或 GiB 小时填写单价，GPU 从 GPU 目录选择类型与分配方式。
2. 选择“镜像构建小时”时，填写部署配置中的构建器标识（例如 `buildkit-primary-v1`，不能含空格）。没有匹配构建费率的构建会被拒绝。
3. 选择模型 token 单位时，填写网关实际调用的模型标识、每百万 token 单价和“单次调用最多预占”。同一模型的输入、输出、缓存读取和缓存写入四类费率都配置后，模型调用才能开始。
4. 填写未来的生效时间，点击“创建费率版本”。历史费用保留原费率快照，不会重新计价。

### 费用估价

选择项目后，“费用估价”可以按当前费率估算资源申请和镜像构建的 CREDITS 上限，不预占资金也不占用容量。资源申请分别填写计算时长和存储保留时长；镜像构建从已有构建费率的构建器中选择，并填写最长构建时长。缺少费率、GPU 目录无法读取或所选 GPU 类型不可用时，页面先显示中文原因，再在“诊断信息”中给出诊断码和请求 ID。

### 项目 Credits 账户

“项目 Credits 账户”显示可用余额、余额、已预占、已支出、待结算、用量待核实和平台承担的金额，以及账目和预占记录。用量尚未核实时显示待核实的笔数；核实期限（首次未知后 1 小时）到达后预占释放，页面显示“待核实，预占已释放”，不把实际费用显示为零，迟到的费用由平台承担。项目成员在资源申请页只能查看本项目的账户；发放、转移、调整和冲正只对平台管理员显示。

平台管理员按以下步骤操作：

1. 在“管理员账务操作”中选择发放、转移到其他项目、调整或冲正。
2. 填写金额（最多六位小数，调整可填负数）；转移时选择目标项目；冲正时在账目行点击“冲正此条”，或填写原账目条目 ID。
3. 填写原因，点击提交。转移、负数调整和冲正会先弹出确认框，说明对余额的影响；发放和正数调整直接提交。
4. 提交失败时页面显示原因和“重试”。结果尚未确认的操作（例如网络中断、服务暂不可用）列在“以下操作的结果尚未确认”中，刷新页面或切换项目后回到原项目仍会列出；点击“重新提交”或再次提交相同内容都沿用原请求，已入账的操作不会重复入账。提交其他操作或在其他项目操作不会影响这些记录；修改内容会作为新的操作。平台明确拒绝（金额无效、余额不足、账目不存在）的操作不再列出；权限被拒绝时记录保留，换有权限的账号前请先查看账目。浏览器无法保存重试记录时（例如禁用了会话存储或存储已满），页面会注明“刷新后无法安全重试”：本页内重新提交仍沿用原请求，刷新或关闭页面前请先在账目中确认是否已入账。提交后在账户刷新完成前，提交按钮保持不可用。退出登录或切换账号会清除这些记录。已预占的资金不能转出或调减；资金已被预占或消费时冲正会被拒绝。

### 项目 Credits API 与内部预占

平台管理员通过 Credits 管理 API 执行发放、项目间转移、调整和追加冲正；每次写操作都必须提供六位小数金额、原因和稳定的 `Idempotency-Key`。账目只追加，不能覆盖历史。项目成员通过 Access 授权的项目接口读取账户、预占和账目；未授权项目会被拒绝。

配置的 Environment、Task workload owner 通过内部接口创建、结算、释放或标记未知预占。内部接口要求服务 JWT、owner 绑定和稳定幂等键，不能从浏览器或 BFF 调用。费用核算不代表已经支付。接口字段、权限和错误码见[项目 Credits API](contracts/project-credits.md)。


VM 上传使用只包含一个 qcow2 或 raw 磁盘文件的 tar 或 gzip 压缩 tar；裸磁盘文件和容器 OCI 布局归档不能直接用于此入口。表单的磁盘路径填写归档内相对路径，容量填写磁盘的虚拟容量，不是压缩包大小。例如：

```sh
tar -czf vm-template.tar.gz disk/disk.qcow2
```

此例的归档内磁盘路径为 `disk/disk.qcow2`。导入大 VM 镜像后继续查看原导入任务状态；取消后等待页面显示清理完成。状态未知时刷新原任务，不要通过重复导入处理。

## 通知与邮件

通知后端保存资源申请批准/拒绝、租约变更与到期提醒，离线后仍可查询。当前用户通过 `GET /api/v1/notifications` 读取自己的通知，通过 `GET /api/v1/notifications/unread-count` 读取未读数，通过 `POST /api/v1/notifications/{notificationId}/read` 标记已读；重复标记不改变首次已读时间。项目成员和课程关联通知的课程成员必须都有效，撤销或过期任一范围后不可读，也不会领取发送邮件。站内入口由前端消费这些接口，不需要配置 SMTP。

到期提醒读取进程实际加载的平台配置，默认提前 24 小时和 1 小时。申请时长短于提醒窗口时立即记录短租期提示；实际租约开始后，按 Owner 给出的 UTC 起止时间记录提醒。与提醒窗口恰好相等的租约在开始时提醒。页面可转换本地时间，但不能把服务器 UTC 时间解释成本地墙钟。保存新的 desired 不会立即改变已运行进程或既有提醒。

通知只提供对象链接和非受限摘要；打开对象仍须登录并通过当前对象授权。项目权限被撤销后，列表、未读数和已读写入均不再暴露该项目通知。通知不是资源释放证明：停止或撤销授权不表示计算、磁盘已经释放，也不表示账单已经结算。费用和当前状态应在对象及账务页面查询。

管理员在同一个加密 Bundle 配置 `notifications.smtp` 后启用邮件，只发送摘要与对象链接。明确临时拒绝最多尝试 5 次，永久拒绝直接 `failed`。邮件采用 at-most-once：超时、连接断开或发送进程意外退出后显示 `delivery_unknown`，文案“邮件可能已送达，系统无法确认”，不自动重发；站内通知仍保留。没有 IdP 已验证邮箱时为 `no_verified_email`，不重试、不告警；未配置邮件时为 `disabled`。邮件结果不改变账务或资源停止。抢占、欠费保留和账号停用待对应 Owner 事件上线后接入。

## 管理员修改平台配置

平台配置页面管理不含秘密的设置：只读保留、详细日志保留、到期提醒、抢占宽限，以及特权运行的执行位置。只有平台管理员能打开此页面。保存会新增一个 desired 版本，但不会部署，也不会改变当前生效的 applied 版本。

1. 在任务导航中打开“平台配置”。查看“当前事实”：desired 是已保存的期望配置，applied 是最后一次完整验证通过的版本。状态为“待核对”时，先核对外部实际状态。
2. 在“表单”中修改生命周期设置。留存与提醒必须在 1 秒到 365 天之间，提醒最多 16 个且不能重复，抢占宽限为 1–300 秒。到期提醒由 Control 读取实际加载的配置；保存 desired 本身不会发送提醒。清理和抢占由相应领域消费者执行。
3. 如需记录特权执行位置声明，可在“特权运行”中选择“允许，仅在专用节点池运行”，填写 nodeSelector 和 taint。nodeSelector 至少 1 项、最多 16 项；key 的 prefix 最长 253 字符、name 最长 63 字符，value 最长 63 字符且必须非空；taintKey 遵循同样的 key 规则，taintValue 最长 63 字符且必须非空。这些限制比原生 Kubernetes 对应字段更严格。该声明不启用当前容器的 privileged/DinD，执行侧仍拒绝 privileged=true；VM guest 特权位置尚无执行实现，因此不能选择。
4. 点击“保存为新 desired 版本”。也可以在“高级 YAML”中编辑同一请求。
5. 在受限本地目录导出并加密对应 Bundle，然后在“登记加密 Bundle”中选择实际的 `.age` 文件并点击“登记所选 Bundle”。核对页面显示的密文 SHA-256 与本地导出结果一致。登记不是批准，也不是部署。
6. 点击“提交应用请求…”并在确认框中确认。页面只记录请求；获准执行者执行部署并报告阶段。完整验证成功后 applied 才会更新。

普通容器的 capabilities 允许清单、项目/课程普通预授权和默认 UID 已由同一后端契约接入执行消费。表单未提供的字段可通过现有“高级 YAML”编辑同一完整配置：默认 UID 可为 `0..4294967294`，能力只选平台支持且确有需要的集合，scope 预授权不得超过平台允许清单，也不能声明 privileged。保存 desired、登记 Bundle 不等于批准某个实例；实际运行只消费匹配的 verified applied 版本、原配置身份与原资金租约。

builder 的 capabilities、提权和 entitlements 仍无新增执行支持，Control 在保存或 Bundle 登记阶段拒绝这些设置。运行容器的 root 或 NET_ADMIN 不会给平台 builder、executor 服务进程或它们的 ServiceAccount 增权；VM guest 特权位置、广泛内核能力和保留 UID 同样拒绝，不用普通权限切片掩盖未实现边界。

保存时提示“配置已被其他管理员更新”，说明期间有人保存了更新的版本。你的草稿和所选文件都会保留。比较字段差异后，选择“保留我的草稿”继续编辑，或者放弃草稿并载入最新配置，然后再次保存。保存新的 desired 版本会清空已有的 Bundle 登记，需要重新导出并登记。网络中断时，用同一文件按原样重试，不要重新加密生成不同的密文。

## 任务没有完成时

先刷新原任务或返回项目任务历史查看状态。明确失败后阅读可处理的错误信息：第一行说明原因，第二行给出下一步。再使用界面提供的恢复、重试或取消操作；传输结果不明时先查询原任务，不要重复提交。若操作显示完成但环境或资源仍在释放中，继续查看原记录；不要创建重复申请。

向管理员反馈时说明角色、项目名称、想完成的操作、最后看到的状态和错误提示。展开错误提示中的“诊断信息”，点击“复制诊断信息”，把诊断码和请求 ID 一起发给管理员（只有平台返回了请求 ID 时才会显示）。不要发送密码、令牌、私钥或无关用户内容。

## 真实身份边界验证

协议和内部服务 JWT 的增量测试不需要生产凭据：

```sh
cargo test -p auth --test service_auth --locked
cargo test -p access-service --test postgres oidc_binding_is_checked_before_atomic_consumption_and_expiry --locked
```

真实浏览器边界需要 Docker、Node、锁定的 Playwright Chromium 和 PostgreSQL：

```sh
pnpm --dir web install --frozen-lockfile
pnpm --dir web exec playwright install chromium
cargo test -p access-service --bin access-service chromium_oidc_navigation_enforces_browser_binding_and_session_lifecycle --locked -- --ignored --nocapture
```

该用例启动临时真实 Keycloak/HTTPS/PostgreSQL，覆盖双浏览器、多标签、重放、过期、`return_to`、刷新和 provider logout；返回页只用于协议断言，不替代 Vue 门户旅程。测试夹具的自签名证书只由 Chromium 信任；Access 的 OIDC 和服务客户端继续执行严格 TLS。生产 SSH/控制台传输撤销需要 Gateway、sshd、受控服务 JWT/TLS、真实目标端点和 grant 撤销事件，不能用登录夹具或手工 header 代替。
