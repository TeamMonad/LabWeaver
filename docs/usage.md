# 开始使用 LabWeaver

## 登录与项目

管理员开通组织账号并授予相应角色后，从平台首页登录。左侧导航列出当前账号可用的全部功能；个人 Work 使用同一账号，无需切换身份。

首页“进行中”只显示当前项目的事项：运行中的环境、未完成的生成与配置任务，以及待审批或分配中的资源申请。等待审核的任务可以从“去审核”直接进入审核页。首页在打开、切换项目、点击“刷新”和从其他标签页切回时更新；页面在后台时不自动刷新。首页的资源申请列表可能不完整（平台暂时只返回你能看到的申请，且不分页），完整记录在“资源申请”页查看。

点击顶栏“退出”后，浏览器会完成组织登录系统的退出并返回首页。页面提示登录失效时，重新登录再继续原项目；不要重复提交结果不明的任务。

先在“项目与工作空间”创建项目，或由项目负责人将你加入已有项目。教师项目负责人和平台管理员可按组织账号的显示名称或 `username` 搜索并选择成员；学生管理自己的私人项目时，使用受邀者的准确 `username` 添加已知账号。项目编辑、归档和成员管理由项目负责人或平台管理员执行，其他成员可以查看。顶栏项目选择器决定当前操作的归属。地址栏中的 `projectId`、页面标题、选择器和页面数据始终指向同一个项目，刷新或分享链接后仍打开同一项目。选择器支持键盘操作：按上下方向键移动，按 Enter 选择，按 Escape 关闭。切换项目后，页面会重新加载该项目的数据，并清除上一项目中选中的环境或任务。

打开的链接指向你无法访问的项目时，页面显示“无法打开链接中的项目”，并说明“项目不存在或你无权访问”；项目可以读取但不在你的项目列表中时，同样不能在这里打开。页面不会显示其他项目的数据。点击“切换到「项目名称」”回到可访问的项目，或点击“查看我的项目”重新选择；如果你认为应该能访问该项目，联系项目 Owner 或管理员确认。

项目列表加载失败时，项目页面显示“暂时无法确认当前项目”，不会打开任何项目的数据。点击“重试”，列表加载成功后页面才会打开。

Access 的登录入口是门户顶层导航 `GET /auth/login?return_to=<门户路径>`。每个标签页都有独立的 state、PKCE、nonce 和事务 Cookie；不要把另一个浏览器或标签页的 callback URL 复制过来。非法 `return_to`（外部 URL、`//`、反斜杠或控制字符）返回 `400 / LW_AUTH_OIDC_RETURN_TO_REJECTED`。事务 Cookie 缺少或跨浏览器使用返回 `401 / LW_AUTH_OIDC_BROWSER_REJECTED`；重放或过期返回 `401 / LW_AUTH_OIDC_STATE_REJECTED`。

退出请求必须带当前 `Origin` 和 CSRF token。Access 撤销 BFF 会话、清理会话 Cookie，并终止该 BFF 会话的浏览器 Console 连接；随后按响应中的 `logoutUrl` 顶层导航到 Keycloak。SSH 会话使用独立 AccessGrant，按 grant 到期、显式撤销及成员/环境授权变化的规则收尾，BFF 退出不会错误地声称已撤销独立 SSH grant。

项目负责人在“项目 AI 设置”选择可用模型、确认材料范围并设置调用预算。模型服务地址和凭据由管理员在部署侧配置，普通用户无需填写。材料只应包含本次任务所需且已获授权的文件。

## 教师准备实验

1. 选择项目，从教师工作台进入材料页面，上传包含题面、初始源码、样例及环境要求的材料目录。
2. 上传完成后启动实验生成。等待期间查看任务状态；资源待审批时由管理员处理相应申请。
3. 打开“审核与发布”。左侧列出当前项目的实验生成任务，不需要复制任何 ID。
   - “可以审核”：打开后在右侧审核。
   - “未完成”：回到材料页，沿原任务继续处理。
   - “已有发布版本”：页面读取发布时的批准记录，核对材料包、环境和评分规则是否与当前版本一致。完全一致时只显示发布结果；任何一项有变化时，提示需要重新审核。
   - 左侧只列出最近 50 个生成任务。读不到已发布版本或其批准记录时，页面暂停批准，刷新或重试后再批准。
4. 依次查看各标签页：“概览”显示资源规格和每次生成的结果，失败的尝试和诊断码保留在记录中；“环境与权限”显示学生入口、资源和平台当前返回的安全策略；“评分规则”显示每个步骤的分值、检查方式和测试组；“材料”列出材料包文件；“技术详情”列出将要绑定的候选、镜像身份和批准后的发布记录。页面目前没有学生视角预览，也不显示特权模式、capability 用途或发布前估价。
5. 勾选确认并填写批准说明，点击“批准并发布”。一次批准绑定这一版的材料包、环境、运行权限、镜像和评分规则，并自动发布。网络失败后重试或重复点击沿用同一次提交，只产生一个版本。之后材料或配置有变化，会生成新的候选，需要重新审核；已发布的版本不受影响。发布完成后，任务移到“已有发布版本”，可在“已发布环境模板”中查看。链接中的批准记录不属于当前版本时，页面会忽略它并提示，当前版本仍可审核。发布失败时页面显示原因和诊断码，把诊断信息发给平台管理员处理。
6. 将学生加入项目。发布后的实验版本供学生创建环境使用。成员搜索和发布操作完成后刷新项目，确认成员显示名称、username 和角色正确。
7. 从环境页面查看有权管理的实际运行环境。修改运行实例与修改共享实验版本是不同操作；学生从自己的评测结果页面查看提交结果。

## 学生完成实验

1. 选择已加入的实验项目，进入“我的实验”，选择已发布的实验版本并创建项目环境。实验项目可以关联课程，也可以独立使用。
2. 按提示提交资源申请，等待管理员审批与环境启动。等待时可以离开页面，返回后继续查看原任务。
3. 环境就绪后打开环境控制台，签发访问授权并连接浏览器终端或图形控制台。
4. 在自己的运行实例内完成题目要求的源码或系统配置修改。提交时选择对应评测入口；冻结提交针对提交时的输入版本，实时配置检查针对当前实例。
5. 在评测结果中查看成绩、失败原因和反馈。修改后重新提交，不改变已提交版本或共享评分规则。
6. 完成实验后，停止环境可保留工作目录和磁盘，供之后重启；需要归还资源时删除环境，并等待页面显示实际释放。删除前备份需要的文件。“停止中”“释放中”和“已释放”分别表示不同阶段。

## 个人 Work

1. 打开“Work 环境”。页面列出当前项目的 Work 及其固定的模板版本，点击“连接”进入已有 Work。创建和连接 Work 不需要配置模型；项目没有可用模型时，页面顶部说明 Agent 生成与配置不可用，其他操作不受影响。
2. 在“新建 Work”中选择一个已发布模板。卡片显示运行方式（容器或虚拟机）、版本、发布时间和固定的镜像。创建后 Work 固定使用这个版本，模板发布新版本时不会自动替换已有 Work。
3. 点击“下一步：选择资源与时长”。资源申请页面会预先选好该模板版本；填写 CPU、内存、磁盘、时长和所需 GPU，核对页面列出的费率说明后提交，等待审批。页面不提供服务端估价；费率缺失或读取失败时不按免费处理，实际费用以计量和核算为准。
4. 回到“Work 环境”查看进度。“Work 申请”的“准备中”列出已提交但还没有环境的 Work，写明等待审批、正在分配资源、正在创建环境或资源即将到期；平台返回诊断时一并显示原因和诊断码。申请变化期间页面自动刷新，审批通过后平台自动创建环境，Work 随即出现在“项目中的 Work”。
5. 申请被拒绝、已取消或已到期且没有创建 Work 时，列在“未创建成功”中，并显示原因。这些申请不会自动继续：点击“查看资源申请”查看记录，或点击“用同一模板重新申请”提交新的申请。不要在原申请仍在“准备中”时重复提交。
6. 当前项目没有可用模板时，Work 页面会说明下一步。目前 Work 模板只能通过 Agent 生成：在“软件配置”上传任务材料，生成、审核并发布 Work 模板，这一步需要项目 AI 设置中有可用模型。从平台镜像直接发布手工模板需要后端支持，当前版本还不能使用。生成或构建失败时从任务历史打开原任务继续处理，不重复创建模板。
7. 点击 Work 的“连接”打开环境页。“连接”区分开显示实例状态和连接状态：实例运行中不代表已经可以连接。入口仍在检查时显示“入口检查中”，入口就绪但没有访问授权时显示“待授权”，授权生效后显示“可连接”，授权过期或无法确认时显示“待重新授权”。等待入口或授权期间页面每隔几秒自动重新检查，最长约 10 分钟；之后点击“重新检查”。页面切回前台时也会立即重新检查。
8. 在“待授权”或“待重新授权”时点击“签发授权并连接”或“重新签发并连接”。授权生效后，页面按平台为这个授权返回的控制台能力打开第一个浏览器控制台（终端或桌面）；平台没有返回浏览器控制台时停留在概览，使用列出的 SSH 或 Web 应用入口。“连接方式”只列出平台返回的方式：浏览器终端或桌面按访问授权的控制台能力列出，SSH 和 Web 应用按已登记的入口列出。
9. 需要配置软件时，上传配置要求并选择目标 Work；审核生成的脚本、权限和重启影响后批准执行。
10. 查看执行结果。失败后先检查原任务状态，再使用页面提供的恢复或重试操作；重试同一配置应避免重复提交，实际新增用量仍可能产生费用，系统不得对同一用量重复入账。
11. 停止并重新启动环境后，按模板和页面的数据保留说明检查工作区；需要保留的软件配置应写入模板声明的持久化路径，容器 rootfs 中的临时安装不视为持久化。确认任务完成后从页面释放环境并查看费用。

## SSH 与环境生命周期

在“SSH 公钥”登记自己的公钥，私钥留在客户端。环境就绪并获得访问授权后，从环境页面复制完整 SSH 命令并实际连接。连接中断后先检查环境与授权状态，再使用页面命令重连；授权过期时从界面重新签发，撤销后不能继续使用原授权。

停止环境、删除环境和释放资源是不同操作。提交停止不代表已停止计量：环境实际停止后，计算用量才停止计量；保留的工作目录和磁盘继续计入存储用量，直到删除。GPU 容量是否保留取决于环境类型和项目资源配置，以资源与费用记录为准。删除环境会永久删除其工作目录和关联磁盘中的数据，执行前备份需要的文件并阅读页面说明。

点击“停止”或“重启”后，页面先弹出确认框，说明会断开的会话和用量变化；GPU 容量是否保留以资源与费用记录为准。点击确认后才提交操作，点击“取消”或按 Escape 不做任何更改。“启动”不需要确认。确认框打开时焦点默认在“取消”上。提交停止或回收请求后，等待界面显示实际完成；“释放中”不表示容量已经可供下一项任务使用。

环境控制台只在环境处于启动、停止、重启等变化过程中自动刷新状态；环境稳定后停止自动刷新，页面在后台时也暂停，切回标签页时立即刷新一次。需要最新状态时点击“刷新”。

## 使用 GPU

申请资源时选择管理员提供的 GPU 类别和模式，并确认模板支持相应容器或 VM。独占、容器时间片和 VM vGPU 的容量分别由实际设备配置决定；容器时间片只提供共享份额，不提供独占显存或固定比例算力。没有可用容量时，按申请状态等待或联系管理员，不要重复创建申请。

进入环境后运行任务所需的 CUDA 计算，确认数值结果符合预期。VM 中同时确认驱动和许可证状态；设备名称可见不代表计算已经可用。完成后释放环境，等待资源使用授权实际回收，再申请下一项任务。

## 管理员处理资源与费用

管理员先配置可用镜像、执行资源、GPU 目录和费率，再处理用户申请。审批前确认项目、申请人、用途、资源规格和期限。GPU 目录应对应实际可分配设备；设备不可用时处理等待或拒绝申请。

在预算与费用页面选择已授权项目，按环境或任务查看实际计算和存储区间、CPU、内存、存储及 GPU 用量、结算与预算提醒。教学与个人 Work 都进入统一核算。缺少费率、未知用量及尚未结算的记录应继续处理，不能当成零费用；已有历史费用不表示当前任务已结算。费用用于核算，不代表已经支付。需要调整时填写金额和原因；调整追加记录，不覆盖原费用。

VM 上传使用只包含一个 qcow2 或 raw 磁盘文件的 tar 或 gzip 压缩 tar；裸磁盘文件和容器 OCI 布局归档不能直接用于此入口。表单的磁盘路径填写归档内相对路径，容量填写磁盘的虚拟容量，不是压缩包大小。例如：

```sh
tar -czf vm-template.tar.gz disk/disk.qcow2
```

此例的归档内磁盘路径为 `disk/disk.qcow2`。导入大 VM 镜像后继续查看原导入任务状态；取消后等待页面显示清理完成。状态未知时刷新原任务，不要通过重复导入处理。

## 管理员修改平台配置

平台配置页面管理不含秘密的设置：只读保留、详细日志保留、到期提醒、抢占宽限，以及特权运行的执行位置。只有平台管理员能打开此页面。保存会新增一个 desired 版本，但不会部署，也不会改变当前生效的 applied 版本。

1. 在任务导航中打开“平台配置”。查看“当前事实”：desired 是已保存的期望配置，applied 是最后一次完整验证通过的版本。状态为“待核对”时，先核对外部实际状态。
2. 在“表单”中修改生命周期设置。留存与提醒必须在 1 秒到 365 天之间，提醒最多 16 个且不能重复，抢占宽限为 1–300 秒。这些值目前只作为配置保存，清理、提醒和抢占尚未按它们执行。
3. 需要特权运行时，在“特权运行”中选择“允许，仅在专用节点池运行”，填写 nodeSelector 和 taint。VM guest 位置尚无执行侧实现，因此不能选择。
4. 点击“保存为新 desired 版本”。也可以在“高级 YAML”中编辑同一请求。
5. 在受限本地目录导出并加密对应 Bundle，然后在“登记加密 Bundle”中选择实际的 `.age` 文件并点击“登记所选 Bundle”。核对页面显示的密文 SHA-256 与本地导出结果一致。登记不是批准，也不是部署。
6. 点击“提交应用请求…”并在确认框中确认。页面只记录请求；获准执行者执行部署并报告阶段。完整验证成功后 applied 才会更新。

普通容器 capabilities 允许清单、项目/课程预授权、非 0 默认容器 UID，以及 builder 的 capabilities、提权和 entitlements 尚无执行侧实现。页面将这些设置显示为只读，提交包含这些设置的 YAML 会在本地被拒绝。若已保存的 desired 版本含有这些设置，页面会禁止登记和应用；点击“恢复为可部署值”，再保存新版本。

保存时提示“配置已被其他管理员更新”，说明期间有人保存了更新的版本。你的草稿和所选文件都会保留。比较字段差异后，选择“保留我的草稿”继续编辑，或者放弃草稿并载入最新配置，然后再次保存。保存新的 desired 版本会清空已有的 Bundle 登记，需要重新导出并登记。网络中断时，用同一文件按原样重试，不要重新加密生成不同的密文。

## 任务没有完成时

先刷新原任务或返回项目任务历史查看状态。明确失败后阅读可处理的错误信息：第一行说明原因，第二行给出下一步。再使用界面提供的恢复、重试或取消操作；传输结果不明时先查询原任务，不要重复提交。若操作显示完成但环境或资源仍在释放中，继续查看原记录；不要创建重复申请。

向管理员反馈时说明角色、项目名称、想完成的操作、最后看到的状态和错误提示。展开错误提示中的“诊断信息”，点击“复制诊断信息”，把诊断码和请求 ID 一起发给管理员（只有平台返回了请求 ID 时才会显示）。不要发送密码、令牌、私钥或无关用户内容。

## 真实身份边界验证

协议和内部服务 JWT 的增量测试不需要生产凭据：

```sh
cargo test -p auth --test service_auth --locked
cargo test -p access-service --test postgres oidc_binding_is_checked_before_atomic_consumption_and_expiry --locked
```

真实浏览器边界需要 Docker、Node、锁定的 Playwright Chromium 和 PostgreSQL：

```sh
pnpm --dir web install --frozen-lockfile
pnpm --dir web exec playwright install chromium
cargo test -p access-service --bin access-service chromium_oidc_navigation_enforces_browser_binding_and_session_lifecycle --locked -- --ignored --nocapture
```
