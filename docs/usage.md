# 开始使用 LabWeaver

## 登录与项目

管理员开通组织账号并授予相应角色后，从平台首页登录。首页和任务导航只显示当前账号可用的操作；个人 Work 使用同一账号，无需切换身份。

先在“项目与工作空间”创建项目，或由项目负责人将你加入已有项目。顶栏项目选择器决定当前操作的归属。跨页面操作前确认项目名称，避免把材料、环境或费用操作提交到其他项目。

项目负责人在“项目 AI 设置”选择可用模型、确认材料范围并设置调用预算。模型服务地址和凭据由管理员在部署侧配置，普通用户无需填写。材料只应包含本次任务所需且已获授权的文件。

## 教师准备实验

1. 选择项目，从教师工作台进入材料页面，上传包含题面、初始源码、样例及环境要求的材料目录。
2. 上传完成后启动实验生成。等待期间查看任务状态；资源待审批时由管理员处理相应申请。
3. 审核环境和评测候选，查看构建结果及配置内容。失败时先阅读原因，再决定是否重试同一任务。
4. 批准并发布实验版本，将学生加入项目。发布后的实验版本供学生创建环境使用。
5. 从环境页面查看有权管理的实际运行环境。修改运行实例与修改共享实验版本是不同操作；学生从自己的评测结果页面查看提交结果。

## 学生完成实验

1. 选择课程关联项目，进入“我的实验”，选择已发布的实验版本并创建项目环境。
2. 按提示提交资源申请，等待管理员审批与环境启动。等待时可以离开页面，返回后继续查看原任务。
3. 环境就绪后打开环境控制台，签发访问授权并连接浏览器终端或图形控制台。
4. 在自己的运行实例内完成题目要求的源码或系统配置修改。提交时选择对应评测入口；冻结提交针对提交时的输入版本，实时配置检查针对当前实例。
5. 在评测结果中查看成绩、失败原因和反馈。修改后重新提交，不改变已提交版本或共享评分规则。
6. 完成实验后释放不再使用的环境与资源。

## 个人 Work

1. 在项目工作空间上传任务材料，生成、审核并发布 Work 模板。
2. 在资源申请页面选择已发布版本以及 CPU、内存、磁盘和所需 GPU，等待审批。
3. 启动环境并通过浏览器控制台或 SSH 使用。需要配置软件时，上传配置要求并选择目标 Work；审核生成的脚本、权限和重启影响后批准执行。
4. 查看执行结果。失败后先检查原任务状态，避免重复提交相同配置。

## SSH 与环境生命周期

在“SSH 公钥”登记自己的公钥，私钥留在客户端。环境就绪并获得访问授权后，从环境页面复制 SSH 命令。连接中断后先检查环境与授权状态，再重新连接；授权过期时从界面重新签发，撤销后不能继续使用原授权。

停止环境、删除环境和释放资源是不同操作。执行前阅读界面的数据保留与连接中断说明。提交停止或回收请求后，等待界面显示实际完成；“释放中”不表示容量已经可供下一项任务使用。

## 使用 GPU

申请资源时选择管理员提供的 GPU 类别和模式，并确认模板支持相应容器或 VM。独占、容器时间片和 VM vGPU 的容量分别由实际设备配置决定；没有可用容量时，按申请状态等待或联系管理员，不要重复创建申请。

进入环境后运行任务所需的 CUDA 计算，确认数值结果符合预期。VM 中同时确认驱动和许可证状态；设备名称可见不代表计算已经可用。完成后释放环境，等待资源使用授权实际回收，再申请下一项任务。

## 管理员处理资源与费用

管理员先配置可用镜像、执行资源、GPU 目录和费率，再处理用户申请。审批前确认项目、申请人、用途、资源规格和期限。GPU 目录应对应实际可分配设备；设备不可用时处理等待或拒绝申请。

在预算与费用页面选择已授权项目，查看用量、费用及预算提醒。费用用于核算，不代表已经支付。需要调整时填写金额和原因；调整追加记录，不覆盖原费用。

导入大 VM 镜像后继续查看原导入任务状态；取消后等待清理完成。不要通过重复导入来处理状态未知的请求。

## 任务没有完成时

先刷新原任务或返回项目查看状态。明确失败后阅读可处理的错误信息，再使用界面提供的重试或取消操作。若操作显示完成但环境或资源仍在释放中，继续查看原记录；不要创建重复申请。

向管理员反馈时说明角色、项目名称、想完成的操作、最后看到的状态和错误提示。不要发送密码、令牌、私钥或无关用户内容。
