# 开始使用 LabWeaver

## 登录与项目

管理员开通组织账号并授予相应角色后，从平台首页登录。首页和任务导航只显示当前账号可用的操作；个人 Work 使用同一账号，无需切换身份。

先在“项目与工作空间”创建项目，或由项目负责人将你加入已有项目。项目负责人从成员页面按组织账号的显示名称或 `username` 搜索并选择成员；私人项目负责人使用受邀者的准确 `username` 添加已知账号。顶栏项目选择器决定当前操作的归属。跨页面操作前确认项目名称，避免把材料、环境或费用操作提交到其他项目。

项目负责人在“项目 AI 设置”选择可用模型、确认材料范围并设置调用预算。模型服务地址和凭据由管理员在部署侧配置，普通用户无需填写。材料只应包含本次任务所需且已获授权的文件。

## 教师准备实验

1. 选择项目，从教师工作台进入材料页面，上传包含题面、初始源码、样例及环境要求的材料目录。
2. 上传完成后启动实验生成。等待期间查看任务状态；资源待审批时由管理员处理相应申请。
3. 审核环境和评测候选，查看构建结果及配置内容。失败时先阅读原因，再决定是否重试同一任务。
4. 批准并发布实验版本，将学生加入项目。发布后的实验版本供学生创建环境使用。成员搜索和发布操作完成后刷新项目，确认成员显示名称、username 和角色正确。
5. 从环境页面查看有权管理的实际运行环境。修改运行实例与修改共享实验版本是不同操作；学生从自己的评测结果页面查看提交结果。

## 学生完成实验

1. 选择课程关联项目，进入“我的实验”，选择已发布的实验版本并创建项目环境。
2. 按提示提交资源申请，等待管理员审批与环境启动。等待时可以离开页面，返回后继续查看原任务。
3. 环境就绪后打开环境控制台，签发访问授权并连接浏览器终端或图形控制台。
4. 在自己的运行实例内完成题目要求的源码或系统配置修改。提交时选择对应评测入口；冻结提交针对提交时的输入版本，实时配置检查针对当前实例。
5. 在评测结果中查看成绩、失败原因和反馈。修改后重新提交，不改变已提交版本或共享评分规则。
6. 完成实验后，停止环境可保留工作目录和磁盘，供之后重启；需要归还资源时删除环境，并等待页面显示实际释放。删除前备份需要的文件。“停止中”“释放中”和“已释放”分别表示不同阶段。

## 个人 Work

1. 在项目工作空间上传任务材料，生成、审核并发布 Work 模板。生成或构建失败时从任务历史打开原任务继续处理，不重复创建模板。
2. 在资源申请页面选择已发布版本以及 CPU、内存、磁盘和所需 GPU，等待审批。
3. 启动环境并通过浏览器控制台或 SSH 使用。需要配置软件时，上传配置要求并选择目标 Work；审核生成的脚本、权限和重启影响后批准执行。
4. 查看执行结果。失败后先检查原任务状态，再使用页面提供的恢复或重试操作；重试同一配置应避免重复提交，实际新增用量仍可能产生费用，系统不得对同一用量重复入账。
5. 停止并重新启动环境后，按模板和页面的数据保留说明检查工作区；需要保留的软件配置应写入模板声明的持久化路径，容器 rootfs 中的临时安装不视为持久化。确认任务完成后从页面释放环境并查看费用。

## SSH 与环境生命周期

在“SSH 公钥”登记自己的公钥，私钥留在客户端。环境就绪并获得访问授权后，从环境页面复制完整 SSH 命令并实际连接。连接中断后先检查环境与授权状态，再使用页面命令重连；授权过期时从界面重新签发，撤销后不能继续使用原授权。

停止环境、删除环境和释放资源是不同操作。实际停止后，计算用量停止；保留的工作目录和磁盘继续按存储费率核算，GPU 预留与 Work 资源租约仍保留。删除环境会永久删除其工作目录和关联磁盘中的数据，执行前备份需要的文件并阅读页面说明。提交停止或回收请求后，等待界面显示实际完成；“释放中”不表示容量已经可供下一项任务使用。

## 使用 GPU

申请资源时选择管理员提供的 GPU 类别和模式，并确认模板支持相应容器或 VM。独占、容器时间片和 VM vGPU 的容量分别由实际设备配置决定；容器时间片只提供共享份额，不提供独占显存或固定比例算力。没有可用容量时，按申请状态等待或联系管理员，不要重复创建申请。

进入环境后运行任务所需的 CUDA 计算，确认数值结果符合预期。VM 中同时确认驱动和许可证状态；设备名称可见不代表计算已经可用。完成后释放环境，等待资源使用授权实际回收，再申请下一项任务。

## 管理员处理资源与费用

管理员先配置可用镜像、执行资源、GPU 目录和费率，再处理用户申请。审批前确认项目、申请人、用途、资源规格和期限。GPU 目录应对应实际可分配设备；设备不可用时处理等待或拒绝申请。

在预算与费用页面选择已授权项目，按环境或任务查看实际计算和存储区间、CPU、内存、存储及 GPU 用量、结算与预算提醒。教学与个人 Work 都进入统一核算。缺少费率、未知用量及尚未结算的记录应继续处理，不能当成零费用；已有历史费用不表示当前任务已结算。费用用于核算，不代表已经支付。需要调整时填写金额和原因；调整追加记录，不覆盖原费用。

导入大 VM 镜像后继续查看原导入任务状态；取消后等待页面显示清理完成。状态未知时刷新原任务，不要通过重复导入处理。

## 任务没有完成时

先刷新原任务或返回项目任务历史查看状态。明确失败后阅读可处理的错误信息，再使用界面提供的恢复、重试或取消操作；传输结果不明时先查询原任务，不要重复提交。若操作显示完成但环境或资源仍在释放中，继续查看原记录；不要创建重复申请。

向管理员反馈时说明角色、项目名称、想完成的操作、最后看到的状态和错误提示。不要发送密码、令牌、私钥或无关用户内容。
